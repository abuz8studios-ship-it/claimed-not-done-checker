CLAIMED ≠ DONE Checker — App Map

Take-home guide. Snapshot of code at commit aa7a735 — it can drift as the code changes.

What it is

Paste an agent's claim and its evidence, press CHECK IT, get one honest verdict. Pieces: a page shell (index.html), a pure check core (js/engine.js, depends on nothing), a ledger stamp (js/stamp.js), fixed example texts (js/examples.js), a plugin seam (js/adapters/registry.js), and wiring (js/app.js). No server, no storage, no dependencies.

One action through the code

Reference route (3 stops — not toured live)

  1. js/app.js — search checkBtn: the click handler. Reads both boxes, calls the engine, renders the card, stamps, fires sinks.
  2. js/engine.js — search function check: commitments split, each marked support/dispute/unknown by literal word lists, rolled up to one verdict plus meter. The whole law on one screen.
  3. index.html — search verdictCard: where the verdict word, lines, checklist, meter, and stamp land.

To change this, start here

  • Verdict too strict/loose → the word lists at the top of js/engine.js (TERMINAL_STEMS, CONTRADICTION, RUN_MARKERS). Re-run both examples after any change.
  • Card layout/wording → index.html (verdictCard) and js/app.js (render).
  • Look → css/style.css. Verdict colors: .v-VERIFIED / .v-CLAIMED-ONLY / .v-DISPUTED.
  • Future connector (MCP/Google/Microsoft) → new file + one line in js/adapters/registry.js. Never touch engine.js.

A practice to reuse

Pin the verdict before building the page. The two calibration examples in js/examples.js were fixed in devpost/scope.md > The Check Logic (Pinned) before any code existed, with the rule "fix the logic, not the examples." Every slice re-ran them through the real engine (node requiring js/engine.js) and required EX1 → VERIFIED/TESTED, EX2 → DISPUTED/STATED. On your next agent-built project: write the two examples that prove honesty first, and make the build answer to them.

Run it again

Double-click index.html — no install, no network. Press an example button, then CHECK IT.
